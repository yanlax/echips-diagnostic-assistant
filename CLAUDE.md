# Echips Hardware Check — контекст для Claude Code

Tauri 2 приложение для инженеров сервисного центра Echips: диагностика
ноутбука/ПК, установка драйверов, замена материнской платы. См. README.md
(структура, что работает) и HANDOFF.md (что сделано в последней сессии,
что дальше) — читай оба перед началом работы.

## Конвенции проекта (обязательны для нового кода)

- Frontend без сборки: чистый HTML/CSS/JS в `src/`, без фреймворков и npm.
  Один файл `app.js`, состояние в объекте `S`, рендер экранов через
  `render()`/`screen*()`-функции — следуй существующему паттерну.
- Категории тестов — массив `CATS` в `app.js`. Дисковые тесты (`disk`,
  `smart`, `diskread`, `surface`, `diskwrite`) объединены в одну карточку
  дашборда через поле `group` и объект `GROUPS` — на дашборде и в
  автопрогоне/отчёте они всё равно остаются отдельными тестами.
- Профили моделей — `src/profiles.js` (`ECHIPS_PROFILES`): `default` +
  переопределения по модели, объект `tests` задаёт состав и порядок
  автопрогона, остальные поля — пороги (см. комментарии в файле). Реальные
  эталоны по моделям Echips туда ещё не внесены (только пример).
- Каждый тест должен звать `recordDetail(id, {...})` (строки лога, поле
  `auto: {status, note}`, опционально `series` для графика) — это уходит
  в экран деталей отчёта (клик по строке) и в экспорт TXT/JSON. Автовердикт
  нельзя менять без причины в комментарии — это проверяет `mark()`. Вердикт
  нельзя ставить, пока тест ещё выполняется (`busy`-проверка в `mark()`) —
  иначе долгий тест обрывается и пишется «пройден» без данных.
- IPC через `invoke()`/`tauriEvent.listen()` из `window.__TAURI__`
  (`withGlobalTauri: true` в `tauri.conf.json` — НЕ убирать, без этого
  весь `app.js` падает на первой строке, экран остаётся пустым без
  видимой ошибки).
- Rust-команды — в `src-tauri/src/commands/<область>.rs`, регистрировать в
  `lib.rs`. Почти все команды `#[tauri::command(async)]` (выполняются вне
  главного потока — иначе окно замирает на время PowerShell/нагрузки).
  Windows-специфичный код — под `#[cfg(target_os = "windows")]` с
  осмысленным `Err(...)` в `#[cfg(not(...))]`.
- PowerShell — только через `powershell::run_ps`/`run_ps_json`/
  `run_ps_with_status`. Есть постоянный пул из двух PowerShell-процессов
  (скрипты уходят по stdin в base64) с автоматическим откатом на
  «процесс на вызов» при любой проблеме; `ECHIPS_PS_HOST=0` отключает пул.
  Скрипт с `exit`/`exit N` внутри (кроме хвостового `; exit 0`) не пойдёт
  через пул — используй `run_ps_with_status` для таких случаев (установка
  драйверов и т. п.). Таймаут вызова 120 с. Время каждого вызова пишется в
  `%LOCALAPPDATA%\Echips\HardwareCheck\perf.log`. Кодировка вывода —
  UTF-8, не декодировать как cp1251 (регресс уже был).
- Логику, которую можно проверить юнит-тестами без Windows (разбор SMART —
  `smart_parse.rs`, журнал сбоев — `crash_logic.rs`), выноси в отдельный
  файл с `#[cfg(test)] mod tests` и проверяй, скопировав файл в пустой
  `cargo new --lib` с зависимостью `serde` (см. историю коммитов).
- Датчики LibreHardwareMonitor + драйвер PawnIO вшиты в exe
  (`helper/EchipsSensors` → CI собирает `sensors.zip`, установщик
  скачивается и сверяется по SHA-256 — см. `.github/workflows/build.yml`).
  Драйвер ставится сам при первом запуске, без вопросов (см. HANDOFF.md).
  Не трогай пин SHA-256 без явного повода.
- Комментарии и сообщения об ошибках — на русском.
- **Не собирай локально.** На macOS/Linux `cargo check` падает на
  отсутствующих системных библиотеках (GTK/WebKit) и это не связано с
  корректностью кода. Проверка — только через GitHub Actions
  (`.github/workflows/build.yml`, вручную "Run workflow" или пуш тега
  `v*`). Для UI-логики (без реальных Rust-вызовов) вместо этого собери
  минимальный HTML-стенд с `window.__TAURI__.core.invoke` подменённым на
  функцию-заглушку с тестовыми данными, открой его через встроенный
  браузер и прогоняй сценарии `mcp__Claude_Browser__javascript_tool`
  (так делалось во всех сессиях — см. историю). Rust-код вычитывай
  особенно внимательно на совпадение имён полей (camelCase после serde
  на стороне JS vs snake_case в Rust).
- Версии: при каждом релизе синхронно поднимаются `src-tauri/Cargo.toml`,
  `src-tauri/Cargo.lock` (запись `name = "echips-diagnostic-app"`),
  `src-tauri/tauri.conf.json` (поля `version` И `title` окна — «Echips Hardware Check vX.Y.Z») и подпись версии в `src/index.html`
  (`v0.x.y · ОТК / сервис`), плюс запись в README.md ("## Версия").
  Коммит "Версия x.y.z", затем тег `vX.Y.Z` и пуш тега. После публикации
  релиза можно удалить старый релиз/тег по просьбе пользователя
  (`gh release delete`, `git push origin :refs/tags/vX.Y.Z`, `git tag -d`).
- Не трогай `tauri.conf.json` / `capabilities/default.json` без
  необходимости — там уже настроены нужные права и `withGlobalTauri`.

## Что уже сделано

См. README.md (подробный список по каждой вкладке) и HANDOFF.md (сводка
последней сессии). Коротко: устройство, батарея, USB/BT/Wi-Fi/LAN,
отпечаток, камера/звук, клавиатура (NumPad, дребезг, залипание), матрица
(полноэкранная), тачпад, диск (здоровье/SMART/чтение/поверхность/запись),
журнал сбоев (склейка+диагноз), активация Windows, автопрогон по профилю,
датчики+вентиляторы (LibreHardwareMonitor/PawnIO, вшиты), стресс-тест
(AIDA64-подобный: CPU/FPU/кэш/память/диск/GPU), экспорт TXT/JSON с
подробностями, кнопки окна (свернуть/развернуть/закрыть), быстродействие
(async-команды, пул PowerShell, кэш, perf.log).

## Приоритетные открытые задачи

1. **Запись SN/UUID (замена платы) — самая опасная задача.**
   `write_smbios_identity` в `src-tauri/src/commands/motherboard.rs` —
   заглушка (валидирует и логирует, не пишет на плату). Не подставляй
   флаги AMIDEWINx64.exe из случайных источников — только если точная
   команда предоставлена явно человеком, ответственным за процедуру в
   сервисе Echips. Аудит-лог (SHA-256 хэш-цепочка) уже реализован и
   должен продолжать писаться при любом исходе попытки.
2. Вынести PIN-коды техников (`TECHS` в `app.js`) из открытого
   фронтенд-кода — сейчас заглушка для прототипа. Предложи вариант,
   уточни у пользователя перед рефакторингом.
3. Определение виновного модуля из минидампа в журнале сбоев — нужен
   образец `.dmp` от пользователя для проверки разбора, не делать вслепую.
4. Профили реальных моделей Echips (`src/profiles.js`) — эталоны CPU/ОЗУ/
   диска пока не внесены, только пример в комментарии.
5. Реальные эталоны/пороги в профиле стоит уточнять по новым отчётам
   пользователя (`.json` из вкладки «Отчёт») — так находились почти все
   баги в этой сессии.

PDF-экспорт отчёта реализован (`src-tauri/src/commands/report.rs`,
команда `save_report_pdf`, шрифт PT Sans в `src-tauri/assets/fonts`) —
проверять по-прежнему только через GitHub Actions.
