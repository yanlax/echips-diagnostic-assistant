# Echips Diagnostic Assistant — контекст для Claude Code

Tauri 2 приложение для инженеров сервисного центра Echips (диагностика
ноутбуков). Полное описание структуры и текущего состояния — в README.md.

## Конвенции проекта (обязательны для нового кода)

- Frontend без сборки: чистый HTML/CSS/JS в `src/`, без фреймворков и npm.
- Глобальная переменная `screen`, IPC через `invoke()`/`listen()` из
  `window.__TAURI__`.
- Утилиты `escapeHtml()`, `showLoading()`, `showError()` в `app.js` —
  использовать везде, не дублировать.
- Новый тест = запись в `tests.js` (id/title/group) + рендер-функция в
  `app.js`, зарегистрированная в объекте `RENDERERS`. Пока рендер-функции
  нет — экран автоматически показывает ручную заглушку
  (Исправно/Неисправно/Пропустить), это нормальное поведение, не баг.
- Rust-команды — в `src-tauri/src/commands/<область>.rs`, регистрировать
  в `lib.rs` через `invoke_handler`. Для PowerShell-вызовов использовать
  `powershell::run_ps` / `run_ps_json` (декодирование cp1251 уже внутри).
- Комментарии и сообщения об ошибках — на русском.
- Приложение работает только с Windows-специфичным API (WMI/PowerShell),
  т.к. устройства — ноутбуки Echips под Windows. Не пытайся собирать
  проект локально на macOS/Linux — сборка под Windows идёт через GitHub
  Actions (`.github/workflows/build.yml`, ручной запуск или тег `v*`).
  `cargo check`/`cargo build` здесь может не проходить из-за
  `#[cfg(target_os = "windows")]` веток — это ожидаемо, не чини под
  другие ОС.

## Задачи по приоритету

Бери по одной, после каждой — отдельный коммит с понятным сообщением на
русском. После каждой доработки обновляй README.md (разделы "Что уже
работает" / "Что оформлено как заглушка").

1. Камера и микрофон — тест через `navigator.mediaDevices.getUserMedia()`
   во фронтенде (без Rust-команд): live-превью камеры, запись/плейбек
   короткого аудио с микрофона. Обработать отказ в доступе к устройству.
2. USB-порты — Rust-команда `list_usb_devices` на основе
   `Get-CimInstance Win32_USBHub` / `Win32_PnPEntity`, экран со списком
   подключённых устройств и ручной отметкой по портам.
3. Wi-Fi/Bluetooth — команда `get_network_adapters` (`Win32_NetworkAdapter`,
   фильтр по Wi-Fi/Bluetooth), статус адаптеров.
4. Батарея — доработать `get_battery_info`: распарсить XML из
   `powercfg /batteryreport /xml /output <path>` для design capacity,
   full charge capacity и health%, вместо текущего частичного
   WMI-ответа.
5. Стресс-тест CPU — Rust-команда, запускающая нагрузку на все ядра на
   заданное время (напр. `std::thread` на число cpus), с прогресс-баром
   на фронтенде; после теста — отметка pass/fail по итогам
   (троттлинг/перезагрузка/зависание техник видит сам, глубокий
   мониторинг температур — отдельная задача).
6. Температуры/обороты кулера — исследуй, что реально доступно без
   сторонних DLL (`MSAcpi_ThermalZoneTemperature` через WMI часто не
   даёт вменяемых цифр на ноутбуках) и предложи вариант, прежде чем
   писать код — если потребуется внешняя зависимость (например
   LibreHardwareMonitor CLI), спроси прежде чем тащить её в проект.
7. Отпечаток пальца — минимально: проверка наличия сенсора в системе
   (WMI PnP-устройства с классом Biometric) + ручная отметка результата
   сканирования.

Не трогай `tauri.conf.json` / `capabilities` без необходимости — там уже
настроены нужные права.

Начни с задачи 1, если явно не указано иное.
