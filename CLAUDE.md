# Echips Hardware Check — контекст для Claude Code

Tauri 2 приложение для инженеров сервисного центра Echips: диагностика
ноутбука, установка драйверов, замена материнской платы. Дизайн — из
присланного прототипа `diag.zip`, перенесён по вёрстке 1-в-1. Полное
описание структуры, что реально работает и что осталось заглушкой — в
README.md, прочитай его перед началом работы.

## Конвенции проекта (обязательны для нового кода)

- Frontend без сборки: чистый HTML/CSS/JS в `src/`, без фреймворков и npm.
  Один файл `app.js`, состояние в объекте `S`, рендер экранов через
  `render()`/`screen`-функции — следуй существующему паттерну, не вводи
  новый стиль для новых экранов.
- IPC через `invoke()`/`tauriEvent.listen()` из `window.__TAURI__`
  (`withGlobalTauri: true` в `tauri.conf.json` — НЕ убирать, без этого
  фронтенд получает пустой `window.__TAURI__` и весь `app.js` падает на
  первой же строке с `invoke`, экран остаётся пустым без видимой ошибки).
- Rust-команды — в `src-tauri/src/commands/<область>.rs`, регистрировать в
  `lib.rs` через `invoke_handler`. Все Windows-специфичные вызовы —
  под `#[cfg(target_os = "windows")]` с осмысленным `Err(...)` в ветке
  `#[cfg(not(target_os = "windows"))]` (проект не должен падать при
  случайной сборке не под Windows, просто возвращает понятную ошибку).
- PowerShell-вызовы — только через `powershell::run_ps`/`run_ps_json`/
  `run_ps_with_status`. Кодировка вывода — UTF-8 (`[Console]::OutputEncoding`
  выставляется автоматически внутри хелпера). НЕ декодировать вывод как
  cp1251/windows-1251 — это уже было причиной "кракозябр" в одной из
  предыдущих сборок, регресс не повторять.
- Комментарии и сообщения об ошибках — на русском.
- Не пытайся собирать/проверять проект локально на macOS/Linux —
  `cargo check` падает на отсутствующих системных библиотеках GTK/WebKit
  (нужных Tauri для линковки на Linux), это не связано с корректностью
  самого кода. Сборка и реальная проверка — только через GitHub Actions
  (`.github/workflows/build.yml`, ручной запуск "Run workflow" или пуш
  тега `v*`). Внимательно вычитывай новый Rust-код глазами вместо
  компиляции — особенно совпадение имён полей между Rust-структурой
  (camelCase после сериализации через serde, но в Rust — snake_case) и
  аргументами, которые передаёт `invoke()` из `app.js` (там — camelCase,
  как ждёт Tauri по умолчанию).

## Что уже сделано (см. README.md за подробностями)

Реальные данные: информация об устройстве, батарея (включая health% из
powercfg), USB/Bluetooth/Wi-Fi, отпечаток пальца (наличие сенсора), камера
(getUserMedia), звук (Web Audio), CPU-стресс-тест, установка драйверов
(порт логики из `echips-driver-assistant`), чтение SN/UUID платы с
аудит-логом, экспорт отчёта в .txt/.json.

Ручная проверка по дизайну (не баг, не доделывать до автоматики без явного
запроса): клавиатура, дисплей, тачпад.

## Приоритетные открытые задачи

Бери по одной, после каждой — отдельный коммит с понятным сообщением на
русском, обнови README.md (раздел "Требует вашего внимания") если статус
задачи изменился.

1. **Запись SN/UUID (замена платы) — самая важная и самая опасная
   задача.** Сейчас `write_smbios_identity` в
   `src-tauri/src/commands/motherboard.rs` — заглушка: валидирует и логирует
   попытку, но не пишет на плату. Не подставляй флаги AMIDEWINx64.exe из
   случайных источников в интернете (форумы про обход HWID-банов в играх —
   это ненадёжно и рискованно для необратимой операции на реальном
   железе). Подставляй точную команду только если она предоставлена
   явно человеком, ответственным за эту процедуру в сервисе Echips —
   спроси, если её нет в задаче. Аудит-лог (SHA-256 хэш-цепочка) уже
   реализован и должен продолжать писаться при любом исходе попытки.
2. Вынести PIN-коды техников (`TECHS` в `app.js`) из открытого фронтенд-кода
   — сейчас это заглушка для прототипа, не для продакшена. Предложи
   вариант (серверная аутентификация / хеш в конфиге вне бандла) и
   уточни у пользователя, прежде чем делать масштабный рефакторинг.
3. PDF-экспорт отчёта (сейчас только .txt/.json).
4. Bandwidth-тест конкретного USB-порта с контрольной суммой (сейчас —
   только список подключённых устройств).
5. Температуры/обороты кулера — сейчас честный fallback "недоступно" на
   большинстве ноутбуков. Если решите интегрировать
   LibreHardwareMonitor/HWInfo — сначала согласуй подход (внешняя
   зависимость, лицензия), не тащи в проект без обсуждения.
6. GPU-стресс-тест и детекция throttling — зависит от задачи 5
   (нужны частоты/температуры).

Не трогай `tauri.conf.json` / `capabilities/default.json` без необходимости
— там уже настроены нужные права и `withGlobalTauri`.
