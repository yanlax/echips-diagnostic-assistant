# Передача сессии — Echips Hardware Check

Последняя версия: **v0.7.2** (тег и релиз на GitHub, старые релизы/теги
удаляются по просьбе пользователя, актуален только последний).

## Что сделано

Изначально: каркас диагностики (устройство, клавиатура/дисплей/тачпад
вручную, батарея, отчёт). Затем внедрён реальный дизайн/бэкенд
(`Echips Hardware Check`, порт логики `echips-driver-assistant` для
драйверов), и по этапам:

- **A** — быстродействие: команды `async`, постоянный пул PowerShell
  (авто-откат при сбое), таймауты, кэш дорогих запросов, `perf.log`.
- **B** — отчёт с деталями (клик по строке → лог/график/причина смены
  вердикта), кнопки окна (свернуть/развернуть/закрыть), клавиатура
  (NumPad, счётчик нажатий, дребезг, залипание, Fn-медиа-ряд), SMART:
  системный диск по умолчанию, порог CRC.
- **C** — журнал сбоев (склейка 3 источников в один сбой, справочник
  ~70 кодов, аппаратные события WHEA/диск/TDR, диагноз по шаблону);
  активация Windows (статус + пошаговое устранение: онлайн-активация,
  OEM-ключ из BIOS, перезапуск службы, синхронизация времени, свой ключ).
- **D** — стресс-тест как в AIDA64: выбор нагрузок (CPU/FPU/кэш/память/
  диск/GPU через WebGL), Стоп, живые графики (загрузка/температура/
  частота), защита от перегрева, маркер обрыва (перезагрузка/зависание
  посреди теста фиксируется при следующем запуске).
- **E** — датчики LibreHardwareMonitor + драйвер PawnIO **вшиты в exe**
  (вспомогательный .NET-процесс собирается в CI, установщик PawnIO
  скачивается и пинится по SHA-256). **Драйвер ставится сам при первом
  запуске, без вопросов** (пользователь явно это попросил — приложение
  только для инженеров). Кнопка удаления на вкладке «Датчики» отключает
  автоустановку (флаг в `localStorage`).
- Тест вентиляторов (как SpeedFan): обороты вживую, ручные ползунки
  20–100%, активная проверка отклика (100%/35%), пассивная проверка в
  автопрогоне, автовозврат в авторежим (таймаут 40 с на стороне
  вспомогательного процесса + явный возврат при выходе/закрытии).
- Несколько раундов исправлений по реальным отчётам пользователя (см.
  «Известные баги, уже исправленные» ниже) — это был главный источник
  информации о реальных проблемах, не выдумывай пороги умозрительно.

## В работе / не начато

- **Реальные эталоны профилей моделей Echips** — `src/profiles.js`
  содержит только `default` и пример в комментарии. Нужны настоящие
  данные по CPU/ОЗУ/диску для каждой модели.
- **Замена платы (`write_smbios_identity`)** — сознательно заглушка,
  см. CLAUDE.md, п.1. Не трогать без точной команды от ответственного.
- **Виновный модуль из минидампа** — не реализовано, нужен образец
  `.dmp` для проверки разбора.
- **PDF-экспорт** — только TXT/JSON.
- **PIN-коды техников во фронтенде** — открытый текст, заглушка.

## Следующие шаги (по порядку, если пользователь не скажет иначе)

1. Подождать новый отчёт `.json` с реального теста (ноутбук/ПК Echips),
   разобрать его так же, как предыдущие — это стабильно вскрывает баги.
2. Начать вносить реальные профили моделей Echips, когда будут данные.
3. PDF-экспорт отчёта.
4. Замена платы — только по явному запросу с точной командой.

## Принятые решения и почему

- **PawnIO вшивается и ставится автоматически без диалога** — пользователь
  явно разрешил: «приложение только для инженеров для тестов, можно
  смело вшивать драйвер». Не возвращать вопрос об установке.
- **LibreHardwareMonitor вместо ACPI/WMI** для температур/вентиляторов —
  ACPI почти везде недоступен на реальных машинах (подтверждено
  отчётами), альтернативы (HWiNFO и т.п.) не лицензионно свободны так же
  просто.
- **Троттлинг в стресс-тесте считается только для CPU/FPU/кэш**, не для
  память/диск — их скорость естественно скачет с фазой записи/чтения и
  кэшем SSD, это давало ложные провалы (было в реальном отчёте).
- **Исправленные ошибки WHEA (PCIe AER) — не критичны**, только справка.
  Настоящую тревогу поднимают некорректированные ошибки.
- **Автовердикт нельзя менять без причины в комментарии**, и **нельзя
  ставить вердикт, пока тест ещё выполняется** — оба правила добавлены
  после того, как реальные отчёты показали противоречивые/пустые записи.
- **Стресс-тест не входит в автопрогон по умолчанию** — пользователь
  прямо сказал, слишком долго и тесты вне автопрогона "используются
  редко, проще оставить в выборе для инженера" (аналогично: внешний
  монитор, USB-накопитель).
- **Тесты диска сгруппированы визуально (`GROUPS`), но остаются раздельными
  тестами в автопрогоне/отчёте** — пользователь просил объединить только
  внешний вид дашборда.
- **Обходы активации Windows и подбор AMIDEWINx64 флагов из интернета —
  отказ**: только легальные механизмы / нужна точная команда от
  ответственного человека.

## Известные баги (открытые)

- Разбор минидампа для виновного модуля не реализован и не проверен —
  не включать в тесты без образца `.dmp`.
- SMART-объём записи/чтения для части SSD может быть неверной единицей
  (эвристически скрывается, если < 1 ГБ при >200ч наработки) — не 100%
  надёжно для всех производителей.
- Автоопределение вентиляторов зависит от поддержки контроллера EC в
  LibreHardwareMonitor — на части ноутбуков вентиляторы не находятся,
  это не баг приложения.

## Известные баги (уже исправленные в этой сессии, для истории)

- USB/BT ложные "неисправности" от `Unknown`-статуса хабов → фильтр по
  `Error`/`Degraded`.
- Отпечаток/USB/BT падали с "PowerShell завершился с ошибкой" при
  отсутствии устройства → `exit 0` в скриптах.
- Журнал сбоев считал сбои втрое (3 источника = 3 записи) → склейка.
- Одиночные внезапные отключения на десктопе ошибочно роняли тест →
  порог `unexpectedShutdownsMax`.
- Видеопамять RTX 3080 показывала 4095 МБ (32-битный WMI) → чтение из
  реестра (`qwMemorySize`, 64 бита).
- Стресс-тест: ложный троттлинг диска "до 4% от базовой" → троттлинг
  теперь только для CPU/FPU/кэш.
- Вёрстка тестов: содержимое наезжало на панель вердикта, таблица SMART
  обрезалась → прокрутка, `flex-shrink`.
- Вердикт можно было поставить во время работы долгого теста → тест
  обрывался и писался "пройден" без данных → блокировка в `mark()`.

## Что нельзя трогать без явного запроса/данных

- `tauri.conf.json` / `capabilities/default.json` (права и
  `withGlobalTauri` уже настроены).
- `write_smbios_identity` — не подставлять команды из интернета.
- Пин SHA-256 установщика PawnIO в `.github/workflows/build.yml`.
- Автоустановка PawnIO без диалога — оставлять как есть (осознанное
  решение пользователя).
- Не пытаться собирать Rust локально на macOS/Linux (см. CLAUDE.md).
