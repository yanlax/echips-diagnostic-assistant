# Передача сессии — Echips Hardware Check

Последняя версия: **v0.8.0** (тег и релиз на GitHub, собран и опубликован
через CI успешно — 6м24с, артефакт `Echips-Hardware-Check.exe`; старые
релизы/теги удаляются по просьбе пользователя, актуален только последний).

## Что сделано (этапы A–E — см. историю коммитов до v0.7.2)

Каркас диагностики, реальный бэкенд, отчёт с деталями, журнал сбоев,
активация Windows, стресс-тест как в AIDA64, датчики LibreHardwareMonitor
+ PawnIO вшиты, тест вентиляторов как в SpeedFan — всё это сделано в
прошлых сессиях, подробности в git log и README.md.

## Эта сессия (v0.7.2 → v0.8.0): разбор 17 реальных отчётов + доработки

Пользователь прислал 17 реальных `.json`/`.txt` отчётов с разных моделей
(NB101A, BM156UL-RH/S, F184UL-H, NR156G-M, V156HT-H и др.) с ручными
пометками техника прямо в полях `comment`/`override_reason`. Разбор этих
пометок дал большую часть правок ниже — **так и дальше стоит поступать**:
это самый надёжный источник реальных багов, никогда не выдумывать пороги
умозрительно.

**Сделано и закоммичено (все JS-правки проверены живьём через браузерный
стенд с подменённым `window.__TAURI__.core.invoke` — см. CLAUDE.md про
локальную сборку; Rust-правки проверены только успешной сборкой CI):**

1. **PDF-экспорт отчёта** — `src-tauri/src/commands/report.rs`, команда
   `save_report_pdf`, шрифт PT Sans (SIL OFL, кириллица) вшит из
   `src-tauri/assets/fonts`. Зависимость `printpdf = "0.7"` (пин версии
   0.7 — API 0.8+ сильно другой, "html"-фичи и переписанный движок).
   При первой сборке CI поймал borrow-checker ошибку (E0502: `font`
   держал `&self` живым дольше, чем можно при `&mut self` в
   `ensure_space`) — пофикшено клонированием `IndirectFontRef` (это
   дешёвая обёртка над `String`, `Clone` есть из коробки).
2. **Автопрогон: интерактивные тесты первыми.** `CATS` получили флаг
   `interactive:true` (kb, lcd, bright, cam, pad, snd, rem), `autoStart()`
   стабильно переставляет их в начало очереди, состав/групповой порядок
   из профиля не меняются.
3. **Тест «Драйверы» (`drv`) в диагностике/автопрогоне** — только
   проверка через уже существующую команду `list_problem_devices`, ничего
   не устанавливает, пишет «поставить можно во вкладке "Установка
   драйверов"». Добавлен в `profiles.js` сразу после активации.
   (Отдельно проверил порт `echips-driver-assistant` — автоопределение
   модели по серийнику (`find_by_serial_prefix` + `normalize_code`)
   корректно совпадает с реальным каталогом на Яндекс.Диске — ключи вида
   `BM156UL-RH`, `F184UL-H` после нормализации точно бьются с префиксами
   серийников из отчётов. Если пользователь снова увидит «не определено
   автоматически» — нужен конкретный серийник для разбора, вслепую здесь
   чинить нечего.)
4. **Активация Windows: автоустранение при провале.** При `fail` тест сам
   без подтверждения на каждый шаг пробует штатные шаги по очереди —
   синхронизация времени → перезапуск службы лицензирования → онлайн-
   активация → (если в BIOS есть OEM-ключ) его установка, с остановкой на
   первом успехе. Лог каждого шага виден в подробностях. Ввод стороннего
   ключа остаётся ручным (нужны данные от техника). Если не помогло —
   прежние кнопки ручного разбора никуда не делись.
5. **Стресс-тест: убран ложный троттлинг.** Просадка «Мопс/с» у
   cpu/fpu/cache относительно базовой раньше считалась троттлингом сама
   по себе — на слабых CPU без турбо (N95/N150, Ryzen U) это ловилось на
   каждом ноутбуке, хотя частота CPU не менялась вообще (два реальных
   прогона одной и той же модели, техник явно написал «ТРОТТЛИНГА НЕТ»).
   Теперь просадка скорости считается неисправностью только вместе с
   реальным падением частоты в этом же прогоне (`clockMinMhz/clockAvgMhz
   < 0.93`); без данных о частоте — не считается вовсе. Проверено на
   числах из реальных отчётов.
6. **Wi-Fi: не ронять тест из-за виртуальных Wi-Fi Direct адаптеров.**
   `list_wifi_adapters` (hardware.rs) теперь зовёт `Get-NetAdapter
   -Physical`, как уже делает `list_lan_adapters` — раньше виртуальные
   адаптеры (`Microsoft Wi-Fi Direct Virtual Adapter`, статус почти
   всегда `Not Present`) роняли тест даже при рабочем физическом
   адаптере с хорошим сигналом.
7. **Диск: поверхность** — график скорости теперь красится по доле
   пройденного диапазона скана (`pos_mb/total_mb`), а не по абсолютной
   позиции на диске: при сканировании части диска (не «весь диск»)
   график раньше оставался почти пустым. Метки нечитаемых блоков
   пересчитаны в ту же систему координат. В строке прогресса появились
   живые мин/макс скорости во время сканирования, не только текущая.
8. **Журнал сбоев**: формулировка про внезапные отключения теперь честно
   говорит, что `Kernel-Power 41` не отличает реальную потерю питания от
   удержания кнопки (в т. ч. техником при тестировании) — это ограничение
   самой Windows, программно не решается. Порог `unexpectedShutdownsMax`
   не менялся.
9. Мелочи: raw SMART-атрибута 194/190 (Temperature) показывал мусорное
   многобайтовое число — теперь явно "45 °C (мин/макс в старших байтах
   raw, hex …)"; дублирующиеся подписи слотов ОЗУ («DIMM 0» дважды на
   части плат) нумеруются "(#2)".

**Пункт "вердикт для стресс-теста"** из первоначального плана — при
проверке оказался НЕ багом: `screenStress()` уже вызывает `verdictBar()`,
кнопки пройден/не пройден/не применимо там есть (внизу длинного экрана,
под графиками). Технику, похоже, просто не попались на глаза — комментарий
про троттлинг он дважды писал в поле «Вентиляторы» по соседству. Ничего
не чинилось.

## В работе / не начато

- **Реальные эталоны профилей моделей Echips** (`src/profiles.js`) —
  сознательно отложено пользователем на потом, сейчас один профиль
  `default` на все модели. Когда возьмёмся: реальный серийник надёжнее
  строк из BIOS (`device_model` часто "Default string"/"To be filled by
  O.E.M." — сами производители материнок не прошивают), а префикс
  серийника (`BM156ULRH`, `F184ULH`, `NR156GM`...) уже подтверждённо
  совпадает с ключами каталога драйверов (см. п.3 выше) — имеет смысл
  сопоставлять профиль по той же логике.
- **Замена платы (`write_smbios_identity`)** — сознательно заглушка,
  см. CLAUDE.md п.1. Не трогать без точной команды от ответственного.
- **Виновный модуль из минидампа** — не реализовано, нужен образец
  `.dmp` для проверки разбора.
- **PIN-коды техников во фронтенде** — открытый текст, заглушка
  (CLAUDE.md п.2, предложить вариант и согласовать перед рефакторингом).
- **Смена тем (light/dark и т.п.)** — пользователь явно попросил делать
  это последней задачей, после всех текущих доработок. Ещё не начато.

## Принятые решения и почему

- **PawnIO вшивается и ставится автоматически без диалога** — осознанное
  решение пользователя, не возвращать вопрос об установке.
- **LibreHardwareMonitor вместо ACPI/WMI** для температур/вентиляторов —
  ACPI почти везде недоступен на реальных машинах.
- **Троттлинг в стресс-тесте требует падения частоты CPU**, не только
  просадки Мопс/с/ГФлопс — см. п.5 выше, подтверждено двумя реальными
  прогонами с явным комментарием техника.
- **Профили моделей — один `default` на все, пока пользователь явно не
  попросит иначе** — сознательный выбор в эту сессию, не начинать
  профили по серийнику без отдельного запроса.
- **Активация Windows: автоустранение без подтверждения на каждый шаг**
  — прямая просьба пользователя в этой сессии; ввод стороннего ключа
  остался ручным, т.к. требует данных, которых у приложения нет.
- **Автовердикт нельзя менять без причины в комментарии**, и **нельзя
  ставить вердикт, пока тест ещё выполняется** — правила из прошлых
  сессий, не трогать.
- **Обходы активации Windows и подбор AMIDEWINx64 флагов из интернета —
  отказ**: только легальные механизмы / нужна точная команда от
  ответственного человека.

## Известные баги (открытые)

- Разбор минидампа для виновного модуля не реализован и не проверен —
  не включать в тесты без образца `.dmp`.
- SMART-объём записи/чтения для части SSD может быть неверной единицей
  (эвристически скрывается, если < 1 ГБ при >200ч наработки).
- Автоопределение вентиляторов зависит от поддержки контроллера EC в
  LibreHardwareMonitor — на части ноутбуков не находятся, это не баг.
- `Kernel-Power 41` не отличает реальную потерю питания от удержания
  кнопки техником — ограничение источника данных Windows, см. п.8 выше.

## Что нельзя трогать без явного запроса/данных

- `tauri.conf.json` / `capabilities/default.json` (права и
  `withGlobalTauri` уже настроены).
- `write_smbios_identity` — не подставлять команды из интернета.
- Пин SHA-256 установщика PawnIO в `.github/workflows/build.yml`.
- Автоустановка PawnIO без диалога — оставлять как есть.
- Не пытаться собирать Rust локально на macOS/Linux (см. CLAUDE.md) —
  только через GitHub Actions; в эту сессию так и был найден и
  исправлен borrow-checker баг в PDF-генераторе (п.1 выше) — сборка CI
  после пуша тега — единственный способ проверить Rust-правки.
