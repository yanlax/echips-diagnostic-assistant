Дальше: замечания пользователя по дизайну, этап перед выдачей сервисам (PIN с хэшами в exe), ожидание завода (OA3/DPKTool, MAC, схемы, прошивка BIOS).
Репозиторий кода: `yanlax/echips-diagnostic-assistant` (публичный). С v0.51.0 отчёты, инженеры и профили живут на собственном

## Что появилось с v0.12 по v0.33 (коротко)

- **Автообновление** (`update.rs`, `src/update.js`): баннер «Доступна версия»,
  источник — GitHub Releases. Файл сохраняется как
  `Echips-Hardware-Check-vX.Y.Z.exe` (v0.25.0: раньше падало, если программа
  запущена из «Загрузок» под тем же именем).
- **Клавиатура**: правый Ctrl — отдельная клавиша; фантомный Ctrl от AltGr
  гасится; PrtScr, медиа-клавиши и F5/F11/F12 глушатся хуком и
  ретранслируются в приложение (`keyhook.rs` → событие `hook-relay-key`);
  блокировка Win подтверждена рабочей по `keyhook.log` (запись keyhook.log отключена).
- **PDF-отчёт** — тема «Графит» (тёмный фон на всех страницах, палитра в
  `report.rs::palette()`, заливка карточек до содержимого).
- **Вход по PIN** (с v0.51.0 — `commands/srv.rs`, `app.js` lock*): экран только с PIN; PIN проверяет сервер Echips, сессия 12 ч;
  без интернета — по «аренде» на 7 суток (подписана сервером, хранится DPAPI-зашифрованной, проверяется публичным ключом
  `data/lease_pub.txt`). Первый вход на ноутбуке и вход после 7 суток без сети требуют интернета. PIN хранится только в
  памяти процесса (тихий повторный вход при истечении токена или появлении связи). Очередь отчётов без сети — на диске; в
  WinPE (X: — ОЗУ) очередь лежит рядом с exe (`reports_queue`). Админ: вкладки «История» и «Журнал», экран «Инженеры»
  (без токенов и ключей — всё на сервере), панель Shift+F10 (журнал всех `invoke`). Новый админский функционал вешать на
  `isAdmin()`. Флаг `FEATURE_PIN=false` включает автовход под Максимом (только для тестов, сервер тогда недоступен).
  История схемы входа: до 0.36 — публичный `data/techs.json`; 0.50 — подписанный список в приватном `echips-reports`;
  0.51 — сервер (подробно в README, раздел «Сервер Echips»).
- **[устарело, с 0.38.0 функция включена — см. верх файла] Замена платы была ВРЕМЕННО ВЫРЕЗАНА** (по просьбе пользователя, после теста на ноутбуке с BIOS 2025 г.: заводские
  утилиты не поддерживают BIOS): флаг `FEATURE_MB = false` в `app.js` скрывает плитку и блокирует `go('mb')`;
  код, экраны и Rust-команды (`motherboard.rs`, вшитые утилиты `assets/smbios`) остались. Вернуть: `FEATURE_MB = true`
  и заменить утилиты на новые от завода. Ниже описано состояние кода.
- **Замена платы** (код сохранён): отдельного PIN-шага нет (инженер из общего входа). Запись
  SN/UUID (`motherboard.rs`, модуль `flash`) по заводской процедуре:
  AMI — `Amidewin.exe /BS /SS`, Insyde — `H2OSDE-Wx64.exe -W -BS -SS`, UUID
  `/SU` / `-SU`; проверка чтением обратно; утилиты и драйверы вшиты
  (`src-tauri/assets/smbios`, распространение разрешил завод-разработчик).
  Серийник 4–40 символов. Любой исход пишется в аудит-лог.
- **Отправка отчётов** (`upload.rs` → сервер): после автопрогона (любой выход в отчёт), при экспорте (только если содержимое
  изменилось), раз в ~10 с для отдельных тестов; путь `<инженер>/<дата>/[<приёмка>_]<серийник>/<время>[_before|_after][_full|_express]`
  (.json и .pdf), обновляется тем же файлом; очередь при отсутствии сети или входа. Первый сегмент пути сервер подставляет из
  сессии; отчёты другого инженера остаются в очереди до его входа. Токенов в exe нет.
- **Автоустранение активации**: последним шагом нажимается «Устранение
  неполадок» в Параметрах через UI Automation.
- **Отчёт**: серийник платы и UUID в «Системной информации».
- **WinPE** (`winpe.rs`): ищется переносимый WebView2 рядом с exe, выставляются
  переменные среды; см. README «Работа в WinPE».
- **USB-порт**: класс порта (USB 2.0/3.x) по скорости чтения; **датчики**:
  запасной источник — счётчик ThermalZoneInformation. GPU-стресс и троттлинг
  были реализованы раньше (README раньше ошибочно писал, что нет).

## Ждёт проверки на реальной Windows (код в релизах, не проверялось)

00. Активация на неактивированной Windows (v0.28.0): раньше запрос статуса падал на
   `[int]$p.LicenseStatusReason` (UInt32 > Int32.Max) — по скриншоту пользователя
   (Windows 11 Домашняя, код 0x800704CF «нет связи с серверами активации»);
   исправлено на `[uint32]`, автоустранение теперь должно запускаться. Реальный
   отчёт (`echips-reports`, Максим, A100ER…324, v0.26.0): драйверы — неисправно (5
   устройств без драйверов, видео — базовый адаптер), плата и модель — заводские
   «OEM default string inject» (подходит для проверки записи SN/UUID).

0. Вход после добавления инженера (v0.26.0): пользователь жаловался, что добавленный
   инженер не виден при перезаходе — исправлено чтением через GitHub API; если снова
   не входит без предупреждения про кэш — смотреть длину/ввод PIN.

1. Запись SN/UUID — **реальный тест (фото пользователя, ноутбук Максима, BIOS GRTY-BI-15.6-A140PR310-052-C
   2025 г.): AMIDEWIN v5.15 (2014) отвечает `d7 - Error: System doesn't support`** — утилита не поддерживает
   этот BIOS; приложение отработало штатно (ошибка + аудит-лог). Нужна более новая версия AMIDEWIN (Aptio V)
   от разработчиков завода. Добавлена проверка поддержки до записи (`check_supported`) и понятное сообщение.
   **Подтверждено (фото 2): заводской `FlashSerialNumber.cmd` («Flash SN for AMI BIOS», v4.17.705) на том же
   ноутбуке тоже пишет «Failed to write SN to BaseBoard»** — комплект утилит завода устарел для этой модели,
   наша программа ни при чём. Ждём от завода новую AMIDEWIN (Aptio V) или другой способ записи.
   Также: UUID на AMI (`/SU`) не подтверждён заводским скриптом;
   драйвер AMI (2014) может блокироваться Защитником/HVCI — причина сбоя
   попадёт в аудит-лог (`failed: …`).
2. Автоустранение активации (кнопка в Параметрах).
3. Отправка отчётов на сервер (вход онлайн и офлайн, очередь, тихий повторный вход), PDF в теме «Графит», вкладки
   «История» (читаемый отчёт, скачивание PDF/JSON/TXT) и «Журнал», экран «Инженеры» — всё на реальной Windows не проверялось.
4. Вход по PIN без интернета (аренда 7 суток, DPAPI), метка «без сети» в шапке.
5. Запуск в WinPE с переносимым WebView2: в Sergei Strelec (Windows PE 11, 22621.1483) окно создаётся,
   но страница не грузится и процесс зависает (~18 МБ, без msedgewebview2 — не подтверждено: у
   пользователя была опечатка в tasklist). Диагностические логи (echips-startup.log, лог Chromium,
   сторож, перехват исключений) добавлялись в v0.27–0.30 и удалены в v0.32.0 по просьбе пользователя
   (в истории git). Нужны компоненты образа: WMI, NetFX, Scripting, PowerShell, StorageWMI, DismCmdlets.
6. Автообновление после исправления имени файла.

## Принятые решения и почему

- **Диагностические лог-файлы отключены по просьбе пользователя** (v0.32.0): `echips-startup.log` и
  `echips-webview2.log` (WinPE: логи запуска, сторож, перехват исключений, лог Chromium — удалены из
  кода), `keyhook.log` и `perf.log` (функции log/perf_log — пустые заглушки). Остались только
  функциональные файлы: аудит-лог замены платы, очередь отчётов, кэш списка инженеров, лог установки
  драйверов, маркер стресс-теста. Зависание в WinPE без диагностики не разобрать — вернуть из истории
  git (коммиты «WinPE: сторожевой поток…», «WinPE: журнал событий…»).

- PawnIO вшит и ставится сам без диалога; LibreHardwareMonitor вместо ACPI.
- Троттлинг стресс-теста подтверждается падением частоты CPU.
- Автовердикт нельзя менять без причины; вердикт нельзя ставить, пока тест идёт.
- Обходы активации Windows — отказ. Подбор флагов утилит из интернета — отказ:
  запись SN/UUID сделана только по заводским скриптам.
- **Сервер вместо GitHub** (0.51.0): вшитый в exe токен извлекаем, а контроля за инженерами (кто входил, начал ли
  диагностику, дошёл ли отчёт) GitHub не даёт. Выбрана бессерверная схема Yandex Cloud (функция + шлюз + бакет): в России
  Cloudflare и зарубежные VPS часто блокируют, российский VPS дороже. Данные — онлайн, без токенов и файлов рядом с
  приложением; исключение — зашифрованная DPAPI аренда для входа без интернета.
- PIN 4 цифры — временно (сервер блокирует перебор: 5 попыток за 15 минут), позже 6.
- Автообновление остаётся на GitHub Releases (публичный репозиторий), от сервера не зависит.
- Ключи Windows из `test1/TEST_TOOL/2.txt` (заводской комплект) не использовать.

## Инфраструктура (сервер, доступы, секреты)

- Yandex Cloud: облако `cloud-drizzle-936`, каталог `echips`. Функции `echips-api` (сервер) и `echips-backup` (ночная копия),
  API Gateway `echips-gw`, бакеты данных и копии (имена — `server/DEPLOY.md`), сервисный аккаунт `echips-server`.
  Управление: веб-консоль или `yc` (`~/yandex-cloud/bin`, `export PATH=$HOME/yandex-cloud/bin:$PATH`; авторизация `yc init`
  делает пользователь). SSH-сервера нет.
- Секреты не в репозитории: `SESSION_SECRET`, `LEASE_KEY` — переменные окружения функции; приватный ключ аренды хранится у
  пользователя (`~/Desktop/Projects/echips-signing-key.txt`, вне репозитория; потеря = новый ключ, новый
  `data/lease_pub.txt` и релиз). Обновление кода функции и переменных — `server/DEPLOY.md`.
- Секрет CI `ECHIPS_REPORTS_TOKEN` и токены GitHub больше не нужны (сборка их не использует).
- Резервная копия бакета — каждую ночь; версионирование включено.
- Портал: `portal/README.md` (домен `service.echips.ru`, DNS у системного администратора в Яндекс 360).

## Что нельзя трогать без явного запроса

- `tauri.conf.json` (кроме версии) / `capabilities/default.json`.
- Пин SHA-256 установщика PawnIO в `.github/workflows/build.yml`.
- Команды записи SN/UUID — только по заводским скриптам.
- `#[cfg(target_os = "windows")]`-код `cargo check` на macOS не видит —
  корректность подтверждает только CI и реальный тест на железе.
