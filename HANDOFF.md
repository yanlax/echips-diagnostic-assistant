# Передача сессии — Echips Hardware Check

Актуально на **v0.25.0** (тег и релиз на GitHub, сборка Actions зелёная).
Репозиторий кода: `yanlax/echips-diagnostic-assistant` (публичный),
репозиторий отчётов: `yanlax/echips-reports` (приватный).

Читай вместе с `CLAUDE.md` (конвенции) и `README.md` (что где работает).

## Что появилось с v0.12 по v0.25 (коротко)

- **Автообновление** (`update.rs`, `src/update.js`): баннер «Доступна версия»,
  источник — GitHub Releases. Файл сохраняется как
  `Echips-Hardware-Check-vX.Y.Z.exe` (v0.25.0: раньше падало, если программа
  запущена из «Загрузок» под тем же именем).
- **Клавиатура**: правый Ctrl — отдельная клавиша; фантомный Ctrl от AltGr
  гасится; PrtScr, медиа-клавиши и F5/F11/F12 глушатся хуком и
  ретранслируются в приложение (`keyhook.rs` → событие `hook-relay-key`);
  блокировка Win подтверждена рабочей по `keyhook.log`.
- **PDF-отчёт** — тема «Графит» (тёмный фон на всех страницах, палитра в
  `report.rs::palette()`, заливка карточек до содержимого).
- **Вход по PIN** (`techs.rs`, `app.js` lock*): список инженеров в
  `data/techs.json` (только SHA-256(salt+":"+pin), роль `tech`/`admin`),
  подтягивается при старте в обход кэша raw.githubusercontent, кэш на диске.
  Экран — только PIN (без выбора имени), инженер определяется перебором хэшей.
  Админ (сейчас только Максим): экран «+ добавить инженера» (добавление,
  смена PIN, удаление — коммит `data/techs.json` через GitHub Contents API,
  токен админа шифруется DPAPI), панель Shift+F10 (журнал всех `invoke`).
  Новый админский функционал вешать на `isAdmin()`.
- **Замена платы**: отдельного PIN-шага нет (инженер из общего входа). Запись
  SN/UUID (`motherboard.rs`, модуль `flash`) по заводской процедуре:
  AMI — `Amidewin.exe /BS /SS`, Insyde — `H2OSDE-Wx64.exe -W -BS -SS`, UUID
  `/SU` / `-SU`; проверка чтением обратно; утилиты и драйверы вшиты
  (`src-tauri/assets/smbios`, распространение разрешил завод-разработчик).
  Серийник 4–40 символов. Любой исход пишется в аудит-лог.
- **Отправка отчётов админу** (`upload.rs`): после автопрогона (любой выход
  в отчёт), при экспорте (только если содержимое изменилось), раз в ~20 с
  для отдельных тестов; путь `<инженер>/<дата>/<время начала>_<серийник>.json`
  и `.pdf`, обновляется тем же файлом; очередь при отсутствии сети. Токен
  (fine-grained, только `echips-reports`) вшивается в exe из секрета Actions
  `ECHIPS_REPORTS_TOKEN`.
- **Автоустранение активации**: последним шагом нажимается «Устранение
  неполадок» в Параметрах через UI Automation.
- **Отчёт**: серийник платы и UUID в «Системной информации».
- **WinPE** (`winpe.rs`): ищется переносимый WebView2 рядом с exe, выставляются
  переменные среды; см. README «Работа в WinPE».
- **USB-порт**: класс порта (USB 2.0/3.x) по скорости чтения; **датчики**:
  запасной источник — счётчик ThermalZoneInformation. GPU-стресс и троттлинг
  были реализованы раньше (README раньше ошибочно писал, что нет).

## Ждёт проверки на реальной Windows (код в релизах, не проверялось)

1. Запись SN/UUID: UUID на AMI (`/SU`) не подтверждён заводским скриптом;
   драйвер AMI (2014) может блокироваться Защитником/HVCI — причина сбоя
   попадёт в аудит-лог (`failed: …`).
2. Автоустранение активации (кнопка в Параметрах).
3. Отправка отчётов (нужен секрет `ECHIPS_REPORTS_TOKEN` при сборке), PDF в
   теме «Графит» (разорванные карточки без заливки, читаемость мелкого серого).
4. Управление инженерами из приложения (токен админа).
5. Запуск в WinPE с переносимым WebView2 (нужны компоненты образа: WMI, NetFX,
   Scripting, PowerShell, StorageWMI, DismCmdlets).
6. Автообновление после исправления имени файла.

## Открытые задачи

- **Ключ Windows (OA3) в BIOS** — не сделано. Заводской `FlashKey.cmd` берёт
  ключ с закрытого сервера завода и отчитывается в Microsoft (IP и пароль там
  в открытом виде — **не переносить**). Нужен образец файла от
  `OATool.exe BIOSOA.bin -r` (Insyde) — формат файла для `-keychk` неизвестен;
  для AMI команд нет.
- **Виновный модуль из минидампа** — нужен реальный `.dmp` (отложено).
- **Профили реальных моделей Echips** (`src/profiles.js`) — отложено.
- Перед выпуском всем сервисам: токены с ограниченным сроком (токен отчётов
  вшит, живёт максимум год); удалить лишний релиз v0.21.0 (отправлял только
  JSON); вход по PIN сейчас включён (на время тестов ненадолго отключали).

## Принятые решения и почему

- PawnIO вшит и ставится сам без диалога; LibreHardwareMonitor вместо ACPI.
- Троттлинг стресс-теста подтверждается падением частоты CPU.
- Автовердикт нельзя менять без причины; вердикт нельзя ставить, пока тест идёт.
- Обходы активации Windows — отказ. Подбор флагов утилит из интернета — отказ:
  запись SN/UUID сделана только по заводским скриптам.
- Токен отчётов вшит в публичный exe (осознанный компромисс, вариант 1):
  ограничен репозиторием отчётов; промежуточный Worker отвергнут пользователем.
- Список инженеров публичный (только хэши PIN) — PIN 4 цифр подбирается
  перебором за секунды, это принято для внутреннего экрана входа.
- Ключи Windows из `test1/TEST_TOOL/2.txt` (заводской комплект) не использовать.

## Работа с пользователем

- Не собирать Rust локально на macOS (явное указание); проверка — GitHub
  Actions. JS-логику проверять браузерным стендом (заглушка `window.__TAURI__`).
- Коммитить и пушить изменения; релиз (`Версия x.y.z` + тег) — по просьбе.
  При `git push` сначала `git pull --rebase`: приложение само коммитит
  `data/techs.json` при добавлении инженеров.
- Сообщения коммитов — на русском, с `Co-Authored-By: Claude Sonnet 5`.
- Система разрешений блокирует: вшивание сторонних бинарников/драйверов,
  правку кода физической записи в BIOS, секреты в CI — только с явным
  разрешением пользователя в чате.

## Что нельзя трогать без явного запроса

- `tauri.conf.json` (кроме версии) / `capabilities/default.json`.
- Пин SHA-256 установщика PawnIO в `.github/workflows/build.yml`.
- Команды записи SN/UUID — только по заводским скриптам.
- `#[cfg(target_os = "windows")]`-код `cargo check` на macOS не видит —
  корректность подтверждает только CI и реальный тест на железе.
